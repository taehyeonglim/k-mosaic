# K-MOSAIC 테스트 전략

> **핵심 관점**: 이 프로젝트에서 가장 위험한 버그는 **앱이 죽는 것이 아니라 조용히 틀린 숫자를 보여주는 것**이다. 공식 통계를 다루는 플랫폼이 잘못된 값을 그럴듯하게 표시하면, 그 숫자는 정책 보고서와 언론에 인용된다.

---

## 1. 위험 기반 우선순위

| 위험 | 발생 가능성 | 영향 | 대응 |
|---|---|---|---|
| **파서가 조용히 잘못된 값 추출** | 높음 (HTML 의존) | 치명 | 구조 단언 + 픽스처 회귀 테스트 + 검증 게이트 |
| **결측이 0으로 변환** | 중간 | 치명 | 타입 강제 + 검증 규칙 V5 |
| **동명 항목 오염** (`학생수` 2개) | 높음 | 치명 | 단위 검사 + 단위 테스트 |
| 비율 계산식 오류 | 중간 | 치명 | 공표치 대조 (V4) |
| 지역 조인 실패 (개칭) | 중간 | 높음 | 매핑표 테스트 |
| API 키 유출 | 낮음 | 치명 | 정적 스캔 + 번들 검사 |
| 접근성 결함 | 높음 | 높음 | axe + 키보드 E2E |
| UI 렌더 버그 | 중간 | 낮음 | 컴포넌트 테스트 |

> **상위 4개가 전부 데이터 정확성**이다. 테스트 투자도 그 비율을 따른다.

## 3. 데이터 검증 (최우선)

`scripts/validate-stats.ts`가 실행하며, **실패 시 스냅숏을 갱신하지 않고 배포를 차단**한다.

| ID | 규칙 | 심각도 |
|---|---|---|
| V1 | 17개 시도가 모두 존재 | 차단 |
| V2 | 시도 합계 = 전국 값 | 차단 |
| V3 | `all` = 초+중+고+각종 합 | 차단 |
| V4 | 계산 비율 vs 공표 비율 ≤ 0.1%p (2024년 이전) | 차단 |
| V5 | 결측이 `0`으로 변환되지 않음 | 차단 |
| V6 | 모든 레코드에 출처 메타 존재 | 차단 |
| V7 | 재실행 시 `retrievedAt` 외 diff 없음 (멱등) | 경고 |
| V8 | 연도 커버리지가 이전 스냅숏보다 축소되지 않음 | 경고 |

**V4가 이 프로젝트의 안전벨트다.** 파서가 깨지거나 분모 표가 개편되면 계산 비율이 공표 비율에서 벗어나므로 즉시 잡힌다. 현재 기준선: 평균오차 **0.0255%p** (n=415).

## 4. 단위 테스트

### 4.1 파서 (`fetch-multicultural-stats`)

**네트워크 없이** 저장된 HTML 픽스처로 검증한다.

| 케이스 | 기대 |
|---|---|
| 정상 표 | 1,080셀 파싱, 연도 6개, 지역 18개 |
| `-` 결측 셀 | `null` 반환 (**`0` 아님**) |
| 표 구조 변경 (열 추가) | **예외 발생** (조용히 통과 금지) |
| 첫 지역이 `전국`이 아님 | 예외 발생 |
| 셀 수 불일치 | 예외 발생 |
| 천단위 구분 `1,234` | `1234` |

> 픽스처에는 **실제 API 키가 포함되지 않는다** — HTML 응답 본문만 저장한다.

### 4.2 KOSIS 클라이언트

| 케이스 | 기대 |
|---|---|
| `학생수` 동명 항목 2개 | `UNIT_NM='명'`인 것만 선택 |
| 설립주체별 축 존재 (`국립`/`공립`/`사립`) | 계 행만 집계, 중복 합산 금지 |
| `err=40` (rate limit) | 지연 후 재시도 또는 명확한 실패 |
| `err=21` (`_S` 표에 objL3) | 축 개수에 맞춰 파라미터 구성 |
| 비표준 JSON (따옴표 없는 키) | 보정 후 파싱 |
| 응답에 API 키 반사 | `redact()` 적용 확인 |

## 6. E2E (Playwright)

소수의 **핵심 흐름**만 다룬다.

| ID | 시나리오 |
|---|---|
| E1 | 첫 화면에 전국 지표·지도·순위가 렌더된다 |
| E2 | 연도 변경 → 지도·지표·순위·추세가 **모두** 갱신된다 |
| E3 | 지표를 비율로 전환 → 척도와 범례가 바뀐다 |
| E4 | **키보드만으로** 지역 선택 → 상세 패널 표시 |
| E5 | 지역 3개 선택 후 4번째 시도 → 제한 안내 |
| E6 | 필터 상태가 URL에 반영되고, 그 URL 재방문 시 동일 화면 |
| E7 | CSV 다운로드에 출처 주석이 포함된다 |
| E8 | 결측 지역에 `—`와 "데이터 없음" 안내가 보인다 |
| E9 | 출처 패널에 통계표 ID와 계산식이 표시된다 |

## 7. 접근성 테스트

| 방법 | 범위 |
|---|---|
| axe (자동) | 전 페이지, CI에서 실행 |
| 키보드 전용 | E4 시나리오 + 전 인터랙션 |
| 스크린리더 (수동) | 지도 `aria-label`, 표 대체 표현 |
| 색상 대비 | 자동 + 다크모드 |
| 색각 시뮬레이션 | 지도 램프 (수동) |

**자동 검사만으로는 부족하다.** "지도의 색이 무엇을 의미하는지 스크린리더로 알 수 있는가"는 axe가 잡지 못한다. §6-E4와 수동 검수를 병행한다.

## 9. CI 파이프라인

```
① 린트 + 타입체크
② 단위 테스트
③ 통합 테스트 (스냅숏 대상)
④ 데이터 검증 (V1~V8)
⑤ 빌드
⑥ 비밀정보 스캔 (S3~S5)
⑦ E2E
⑧ 접근성 (axe)
```

**④가 실패하면 이후 단계를 실행하지 않는다.** 검증되지 않은 데이터로 빌드할 이유가 없다.

수집 스크립트는 CI에서 **자동 실행하지 않는다.** 연 1회 수동 실행 후 결과를 리뷰하고 커밋한다 — 데이터 갱신은 사람이 확인해야 하는 사건이다.

## 10. 하지 않는 것

| 항목 | 이유 |
|---|---|
| 100% 커버리지 목표 | 커버리지는 정확성을 보장하지 않는다. 위험 기반으로 배분 |
| 외부 API 실호출 테스트 | 느리고 불안정하며 rate limit 소비. 픽스처로 대체 |
| 시각적 회귀 스냅숏 (전면) | 유지보수 비용 대비 가치 낮음. 지도 범례 등 핵심만 선별 |
| 수집 스크립트 CI 자동 실행 | 데이터 갱신은 사람의 판단이 필요 |
