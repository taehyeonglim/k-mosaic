# ADR-002. 지도 렌더링 기술

- **상태**: 승인됨
- **일자**: 2026-08-05
- **관련**: [product-requirements.md §7.2](../product-requirements.md), [design-system.md](../design-system.md)

---

## 맥락

MVP 핵심 화면은 17개 시·도 단계구분도(choropleth)다. 브리프 §9가 제시한 판단 기준은 다음과 같다.

17개 시도 GeoJSON 지원 · 반응형 · **접근성** · 툴팁 · **클릭 및 키보드 선택** · 번들 크기 · 유지보수 상태 · 라이선스 · SSR 호환성

여기서 결정적인 것은 **접근성과 키보드 선택**이다. 브리프 §7.2는 "색상만으로 값을 전달하지 않는다", "키보드로 선택할 수 있다", "결측 지역은 다른 패턴으로 표현한다"를 명시했다. 이는 **DOM 노드 단위 접근**을 전제하며, 렌더링 방식(SVG vs Canvas)이 곧 접근성 가능 여부를 결정한다.

또한 대상이 **17개 폴리곤**에 불과하다는 점이 중요하다. 수만 개 피처를 다루는 지도 엔진의 성능 최적화가 전혀 필요 없다.

---

## 검토한 선택지

npm 레지스트리에서 실제 확인한 상태다 (2026-08-05).

| 후보 | 최신 버전 | 최신 배포 | 라이선스 | 렌더링 |
|---|---|---|---|---|
| **d3-geo + topojson-client** | 3.1.1 / 3.1.0 | 2024-03 / 2019-11 | ISC | SVG (직접 제어) |
| react-simple-maps | 3.0.0 | **2022-07** | MIT | SVG |
| ECharts (geo) | 6.1.0 | 2026-05 | Apache-2.0 | Canvas |
| MapLibre GL JS | — | 활발 | BSD-3 | WebGL + 타일 |

### A. d3-geo + topojson-client로 직접 SVG 렌더링

- ➕ **각 시도가 개별 `<path>` DOM 노드** → `tabIndex`, `role="button"`, `aria-label="서울특별시, 22,002명, 3.0%, 전국 2위"` 부여 가능
- ➕ 결측 지역에 SVG `<pattern>`(사선) 적용이 자연스러움
- ➕ SSR 완전 호환 — 서버에서 경로 문자열까지 생성 가능
- ➕ 번들 최소: `d3-geo` + `topojson-client` ≈ 35 KB (gzip 전)
- ➕ 차트와 **동일한 d3-scale 색상 스케일 공유** → 지도·범례·차트의 색이 한 시스템으로 묶임
- ➖ 투영·뷰박스·툴팁 위치를 직접 구현해야 함 (17개 폴리곤 규모에서는 소량)
- ⚠️ `topojson-client` 최신 배포가 2019년 → 사실상 완성된 라이브러리이나, 리스크 회피가 필요하면 **빌드 타임에 GeoJSON으로 변환해 런타임 의존을 제거**할 수 있다

### B. react-simple-maps

- ➕ 선언적 React API로 빠른 구현
- ➖ **최신 배포 2022-07 — 4년간 정체**. React 19+ 호환성 미확인
- ➖ 내부적으로 d3-geo를 감싸므로, 커스텀 접근성 속성을 넣으려면 결국 래퍼를 우회해야 한다 → A의 장점은 잃고 의존성만 추가

### C. ECharts geo

- ➕ 툴팁·범례·시각 매핑이 기본 제공, 유지보수 활발
- ➖ **Canvas 렌더링 → 스크린리더가 지역을 인식하지 못한다.** 키보드 포커스 이동도 기본 지원되지 않는다
- ➖ 번들이 크다 (핵심만 트리셰이킹해도 수백 KB)
- ➖ SSR에서 실제 렌더 불가 (클라이언트 전용)
- **→ 브리프의 접근성 요구와 정면 충돌하므로 탈락**

### D. MapLibre GL JS / Leaflet

- ➖ 타일 기반 슬리피 맵. 17개 행정구역 코로플레스에는 과잉 설계
- ➖ WebGL 컨텍스트, 타일 서버 또는 스타일 호스팅 의존 → 정적 배포(ADR-001)의 단순성을 해침
- ➖ Canvas/WebGL이라 접근성 문제는 C와 동일

## 결정

> **`d3-geo` + TopoJSON을 사용해 SVG를 직접 렌더링한다.**
> TopoJSON → GeoJSON 변환은 **빌드 타임에 수행**하고 런타임에는 GeoJSON만 사용한다.

### 경계 데이터

| 항목 | 내용 |
|---|---|
| 1순위 | 통계청 SGIS 통계지리정보서비스 행정경계 (`sgis.kostat.go.kr`) |
| 라이선스 | **공공누리 제1유형(출처표시)** — 상업적 이용 포함 자유 이용, 변형 허용 |
| 대안 | [`vuski/admdongkor`](https://github.com/vuski/admdongkor) — 데이터 **CC BY 4.0**, 원자료 SGIS 공공누리 1유형 승계, 2026-08 기준 활발히 유지보수 |
| ❌ 사용 금지 | `southkorea/southkorea-maps` — **라이선스 미표기**(license: None), 2018년 이후 방치 |

> **라이선스 미표기는 "자유 이용"이 아니라 "이용 불가"가 기본값이다.** 공공 데이터 플랫폼을 표방하는 프로젝트가 출처 불명 경계를 쓰는 것은 자기모순이므로 명시적 오픈 라이선스만 사용한다.

**출처표시 문구** (지도 하단 및 출처 패널에 상시 노출)
```
행정경계: 통계청 통계지리정보서비스(SGIS) — 공공누리 제1유형
```
`vuski/admdongkor`를 경유하는 경우 저장소 주소도 함께 표시한다.

### 데이터 준비 절차 (Workstream C)

1. SGIS에서 **시도 경계** 원본을 받는다 (행정동 경계를 쓰는 경우 시도 단위로 병합)
2. `mapshaper`로 단순화한다 — 목표 **≤ 150 KB**. 17개 시도 표시에 원본 정밀도는 불필요
3. 각 피처에 `regionCode`(행정표준코드 2자리)를 부여한다 → 데이터 조인 키
4. 울릉도·독도·제주 등 도서 지역이 뷰박스에서 잘리지 않는지 육안 검수
5. 결과를 `public/geo/sido.geo.json`으로 고정하고 **출처·라이선스·취득일·단순화 파라미터를 함께 커밋**

### 접근성 구현 요구 (수용 기준)

| # | 요구 | 검증 |
|---|---|---|
| 1 | 각 시도가 `tabIndex=0`, `role="button"`, 값을 포함한 `aria-label` 보유 | axe / 수동 |
| 2 | Tab으로 17개 지역 순회, Enter/Space로 선택 | 키보드 전용 조작 테스트 |
| 3 | 포커스 링이 색상 대비와 무관하게 보임 | 시각 검수 |
| 4 | 결측 지역은 **사선 패턴 + 범례 항목**으로 구분 (색상 의존 금지) | 시각 검수 |
| 5 | 지도와 동일 데이터를 담은 **표 대체 표현** 제공 | 스크린리더 |
| 6 | 색상 스케일이 색각 이상에서도 순서 판별 가능 | 시뮬레이션 |

> 지도는 보조 표현이고 **표가 정본**이다. 지도를 못 보는 사용자도 동일 정보에 도달할 수 있어야 한다.

### 척도 설계 (브리프 §7.2 대응)

- **학생 수**와 **비율**은 서로 다른 스케일을 쓴다 (수: 값 범위가 넓어 분위수 기반, 비율: 연속 순차형)
- **연도 변경 시 스케일 고정 여부를 사용자가 선택**할 수 있게 한다. 기본은 **전 연도 공통 고정 스케일** — 연도마다 스케일이 재계산되면 실제로 증가한 지역이 같은 색으로 보여 추세를 왜곡한다

## 결과

### 긍정적
- 접근성 요구를 우회 없이 충족
- 번들이 작고 SSR이 자명
- 지도·차트·범례가 하나의 색상 시스템을 공유

### 부정적
- 투영·툴팁·포커스 관리를 직접 구현 (17개 규모에서 수용 가능한 비용)
- 경계 데이터 준비가 선행 작업으로 필요

### 재검토 조건
- 시·군·구(250여 개) 단위로 확장할 때 → SVG 노드 수와 성능을 재평가
- 실제 지형 배경(위성/도로)이 요구될 때 → 타일 기반 엔진 재검토
