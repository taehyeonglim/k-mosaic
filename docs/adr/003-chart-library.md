# ADR-003. 차트 라이브러리

- **상태**: 승인됨
- **일자**: 2026-08-05
- **관련**: [ADR-002](./002-map-library.md), [design-system.md](../design-system.md)

---

## 맥락

MVP가 필요로 하는 차트는 많지 않다 ([PRD §7.6](../product-requirements.md)).

| 화면 | 차트 |
|---|---|
| 전국 개요 | 연도별 추세 (선) |
| 지역 순위 | 가로 막대 |
| 지역 상세 | 학교급별 구성 (막대), 연도 추세 (선) |
| 시계열 분석 | 다지역 비교 선 그래프 (최대 3개) |

데이터 규모는 **540 레코드**로 매우 작다. 성능 최적화나 대용량 렌더링이 필요 없다.

ADR-002에서 지도를 `d3-geo` + SVG로 직접 구현하기로 했으므로, **색상·척도 시스템을 지도와 공유할 수 있는지**가 추가 판단 기준이 된다.

---

## 검토한 선택지

npm에서 실제 확인한 상태다 (2026-08-05).

| 후보 | 버전 | 최신 배포 | 라이선스 | 렌더링 | 의존성 |
|---|---|---|---|---|---|
| **Recharts** | 3.10.1 | 2026-07-25 | MIT | SVG | 11 |
| visx | 4.0.0 | 2026-06-11 | MIT | SVG | 33 |
| ECharts | 6.1.0 | 2026-05-19 | Apache-2.0 | Canvas | 2 |
| Observable Plot | — | 활발 | ISC | SVG | — |
| d3 직접 구현 | — | — | ISC | SVG | — |

### A. Recharts

- ➕ 선언적 React 컴포넌트 — 필요한 4종 차트를 최소 코드로 구현
- ➕ **SVG 기반** → 요소별 `aria-*` 부여 가능, SSR 렌더 가능
- ➕ 유지보수 활발 (2026-07 배포), MIT
- ➕ 내부적으로 d3-scale 계열을 사용 → 지도와 색상 토큰 공유가 자연스러움
- ➖ 세밀한 커스터마이징 시 내부 구조에 의존하게 되는 지점이 있음
- ➖ 기본 접근성이 완전하지 않아 **표 대체 표현을 별도 제공해야 함** (어차피 모든 후보 공통)

### B. visx

- ➕ d3를 React 프리미티브로 감싼 저수준 툴킷. 완전한 제어
- ➖ 축·툴팁·범례를 직접 조립해야 해 **MVP 작업량이 크게 증가**
- ➖ 의존성 33개
- → 커스터마이징 요구가 지금 수준이면 과잉

### C. ECharts

- ➕ 기능 풍부, 툴팁·범례 완비
- ➖ **Canvas 렌더링** — ADR-002에서 접근성 문제로 이미 탈락시킨 방식
- ➖ 번들이 크고 SSR 불가
- → 지도와 차트에서 일관되게 배제

### D. Observable Plot

- ➕ 문법이 간결하고 통계 그래픽에 적합
- ➖ React 통합이 명령형(`useEffect` + ref로 DOM 주입) → 선언적 렌더 트리 밖에 존재
- ➖ SSR 구성이 번거로움

### E. d3로 차트까지 직접 구현

- ➕ 지도와 완전히 동일한 추상화
- ➖ 축·틱·툴팁·반응형 리사이즈를 전부 직접 구현 → **MVP 일정에 부적합**
- → 지도는 폴리곤 17개라 직접 구현이 저렴하지만, 차트는 축·스케일·인터랙션 조합이 많아 비용 곡선이 다르다

## 결정

> **Recharts를 사용한다.** 색상·척도 토큰은 `d3-scale` / `d3-scale-chromatic`으로 정의해 **지도와 차트가 동일한 시스템을 공유**한다.

```
d3-scale, d3-scale-chromatic  ← 단일 색상·척도 시스템
        ├──→ 지도 (d3-geo + SVG 직접)     [ADR-002]
        └──→ 차트 (Recharts)              [ADR-003]
```

이 구성은 "지도는 직접, 차트는 라이브러리"라는 비대칭을 의도적으로 택한 것이다. 근거는 **비용 곡선이 다르기 때문**이다.
- 지도: 폴리곤 17개 + 접근성 요구가 강함 → 직접 구현이 저렴하고 오히려 더 정확
- 차트: 축·틱·툴팁·반응형 조합이 많음 → 라이브러리가 압도적으로 저렴

### 공통 규칙

| # | 규칙 | 이유 |
|---|---|---|
| 1 | 모든 차트에 **표 대체 표현** 제공 (`<table>` 또는 접근 가능한 요약) | 브리프 §11, 스크린리더 |
| 2 | 계열 구분은 색상 + **패턴/마커 형태** 병행 | 색상 단독 전달 금지 |
| 3 | **학생 수와 비율 축을 한 차트에 혼합하지 않는다** | 브리프 §11 "학생 수와 비율을 명확히 구분" |
| 4 | 결측 구간은 선을 **끊는다**. 보간하지 않는다 | 결측을 0이나 추세로 위장 금지 |
| 5 | 분류 변경·시계열 단절 지점에 주석 마커 표시 | 브리프 §7.6 |
| 6 | 축 시작점이 0이 아니면 명시한다 | 과장 왜곡 방지 |
| 7 | 비교 지역은 **최대 3개** | 가독성, 브리프 §7.6 |

### 차트 이미지 저장 기능 (브리프 §7.8)

**MVP에서 제외한다.** SVG → PNG 변환은 폰트 임베딩·해상도·워터마크(출처 표기) 처리가 필요해 난도 대비 가치가 낮다. 대신 **CSV 다운로드**를 제공한다 — 연구·정책 활용에서는 이미지보다 원자료가 유용하다. Phase 2에서 재평가한다.

## 결과

### 긍정적
- 4종 차트를 빠르게 구현, SSR·접근성 기반 확보
- 지도와 차트의 색이 한 시스템으로 묶여 시각적 일관성 확보

### 부정적
- Recharts 내부 구조에 일부 의존
- 기본 접근성이 부족해 표 대체 표현을 반드시 병행해야 함 (규칙 #1로 강제)

### 재검토 조건
- 산점도·상관 분석 등 통계 그래픽이 요구될 때 → visx 또는 Observable Plot 재검토
- Recharts가 React 메이저 버전을 따라오지 못할 때
