# 결정 변경 기록 (Decision Log)

구현 지시서와 기존 설계 문서(`docs/`) 사이에 차이가 발생한 항목을 기록한다.
형식: 기존 결정 → 변경 이유 → 검토한 대안 → 새로운 결정 → 영향

## DL-001. 학생 유형별(국내출생·중도입국·외국인가정) 필터 제외

**기존 결정**
구현 지시서 §4.4는 최소 필터에 "학생 유형"을, §4.7은 지역 상세에 "학생 유형별 구성"을 포함한다.

**변경 이유**
기획 단계 조사에서 **확보 가능한 어떤 출처도 학생 유형별 축을 제공하지 않는다**는 것이 확인되었다 ([data-audit.md §7](./data-audit.md)).
- e-나라지표 F0084의 3개 통계표(`F008401`/`F008402`/`F008403`) 어디에도 유형 축이 없다
- KOSIS 교육기본통계 43개 표 전수 열거 결과 다문화학생 표 자체가 없다
- 지표 정의문에는 유형이 언급되나 이는 "무엇을 다문화학생으로 세는가"의 설명일 뿐, 유형별 분리 집계가 아니다

**검토한 대안**
| 대안 | 판단 |
|---|---|
| KESS(교육통계서비스) 원표에서 취득 | 미검증. 제공 여부 자체가 불확실하며 검증에 시간이 필요 → Phase 2로 이관 |
| 17개 시·도교육청 공공데이터포털 개별 데이터셋 결합 | 교육청마다 스키마·기준일이 달라 통합 시 계보가 훼손됨. 공식 통계로 제시할 수 없음 |
| 유형 비율을 전국 분포로 안분(按分) 추정 | **금지.** 추정치를 공식 통계처럼 표시하는 것은 지시서 §9 위반 |
| 필터를 두되 비활성 상태로 표시 | 채택 |

**새로운 결정**
MVP에서 학생 유형 필터를 **구현하지 않는다.** 대신 필터 영역과 지역 상세 패널에 다음을 명시한다.

> 이 통계는 학생 유형별(국내출생·중도입국·외국인가정) 구분을 제공하지 않습니다.

데이터 스키마에는 `studentType` 필드를 유지하고 MVP 전 레코드에 `'total'`을 채운다 — Phase 2에서 유형별이 확보되면 스키마 변경 없이 확장 가능하다.

**영향**
- 데이터: 없음 (필드는 이미 존재)
- 보안: 없음
- 사용자 경험: 기능 하나가 부재하나, **부재를 명시**함으로써 데이터 오류로 오인되지 않는다. 근거 없는 추정치를 보여주는 것보다 낫다
- 완료 기준: 지시서 §10-6이 "가능한 경우"라는 조건부이므로 충족으로 판정한다

## DL-002. "전국 평균" → "전국 값" 표기 변경

**기존 결정**
구현 지시서 §4.7은 지역 상세에 "전국 평균과의 차이"를 요구한다.

**변경 이유**
전국 비율(4.02%)은 **17개 시·도 비율의 산술평균이 아니라 전국 합계 기반 비율**이다.
- 산술평균: 각 시도 비율을 단순 평균 → 학생 수가 적은 시도가 과대 대표됨
- 전국 값: 전국 다문화학생 수 ÷ 전국 전체 학생 수

두 값은 다르며(경기도 하나가 전체의 28%를 차지하는 분포에서 특히), "평균"이라 표기하면 **통계적으로 틀린 진술**이 된다.

**검토한 대안**
| 대안 | 판단 |
|---|---|
| 산술평균을 실제로 계산해 표시 | 정책적으로 의미가 낮고 오독을 유발 |
| 둘 다 표시 | 화면 복잡도 증가, MVP 범위 초과 |
| 표기만 정정 | 채택 |

**새로운 결정**
UI 문구를 **"전국 값과의 차이"**로 표기한다. 계산은 `region.rate - national.rate` 그대로다.

**영향**
- 데이터·보안: 없음
- 사용자 경험: 표기가 정확해진다. 지시서의 의도(전국 대비 위치 파악)는 그대로 충족

## DL-003. 런타임 MCP 호출 없음 — MCP는 수집 단계 전용

**기존 결정**
구현 지시서 §12-3은 "MCP 연결 방식" 보고를, Agent 1 담당 범위에 `src/lib/mcp/`를 명시한다.

**변경 이유**
[ADR-001](./adr/001-data-ingestion-architecture.md)에서 **정적 스냅숏 아키텍처**를 채택했다. 웹 앱은 런타임에 MCP·KOSIS를 호출하지 않는다. 근거:
- 핵심 데이터(다문화학생 수)가 KOSIS에 **없으므로** 실시간 조회 대상 자체가 부재
- KOSIS 실측 rate limit 200건/분
- 연 1회 갱신 데이터
- 런타임에 API 키가 존재하지 않게 하는 것이 최선의 보안 통제

**새로운 결정**
`src/lib/mcp/`를 **유지하되 Node 전용 모듈**로 둔다. `scripts/`가 import하며, 클라이언트 번들에는 포함되지 않는다. 파일 상단에 `import 'server-only'` 상당의 가드 주석을 두고, 빌드 산출물 검사(E2E-11)로 번들 미포함을 검증한다.

**영향**
- 데이터: 수집 경로는 동일
- 보안: **강화됨** — 런타임 키 부재
- 사용자 경험: 데이터 지연 없음(정적)
- 지시서 §12-3 보고: "MCP는 수집 단계에서만 사용, 런타임 미사용"으로 보고

## DL-004. 학교급 범위 — 유치원·특수학교 제외

**기존 결정**
구현 지시서는 학교급 범위를 명시하지 않으나, 기획 브리프 §5-10은 "유치원, 초등학교, 중학교, 고등학교, 기타학교 포함 범위"를 확인하라고 했다.

**변경 이유**
모수 역검증 결과 이 통계의 분모는 **초+중+고+각종학교**다 ([data-audit.md §5](./data-audit.md)). 특수학교를 포함하면 공표치와의 일치율이 100% → 81.3%로 하락한다. 유치원은 애초에 이 지표의 대상이 아니다.

**새로운 결정**
`SchoolLevel = 'all' | 'elementary' | 'middle' | 'high' | 'other'` (other = 각종학교). 유치원·특수학교는 타입에 두지 않는다.

**영향**
- 데이터: 모수가 공표치와 정합
- 사용자 경험: 학교급 필터에 유치원·특수학교가 없는 이유를 출처 패널에 명시

## DL-005. 차트 이미지 저장 기능 제외

**기존 결정**

**새로운 결정**
MVP에서 제외한다. CSV/JSON 다운로드로 대체한다. ([ADR-003](./adr/003-chart-library.md))

**영향**
- 사용자 경험: 이미지 저장 불가. 브라우저 스크린숏으로 대체 가능

## DL-007. 비율 표시 정밀도 — 소수 1자리

**기존 결정**
문서 간 모순이 있었다.
- `product-requirements.md` §4.1 예시: `4.02%` (소수 2자리)
- `design-system.md` §3.3: "비율 `4.0%` (표시 1자리, 저장 4자리)"

E2E 검증(`docs/qa-report.md`)이 이 충돌을 잡아냈다 — 화면은 `4.0%`인데 PRD 기대값은 `4.02%`였다.

**변경 이유**
표시 정밀도를 하나로 정해야 한다. 판단 근거:
- 출처(교육기본통계·e-나라지표)의 공표 관행이 **소수 1자리**다 (2024년 전남 6.4% 등)
- 2자리로 표시하면 공식 발표치보다 정밀해 보여 "공식 수치와 왜 다른가"라는 오해를 부른다
- 순위 계산은 이미 **저장 정밀도(소수 4자리)** 로 하므로 표시 정밀도가 동률 판정에 영향을 주지 않는다
- 우리가 직접 계산하는 이유는 2025년 공표치가 **정수로 반올림**됐기 때문이다. 1자리만 되찾아도 그 목적은 달성된다 (공표 `4%` → 표시 `4.0%`)

**검토한 대안**
| 대안 | 판단 |
|---|---|
| 소수 2자리 전면 표시 | 지역 간 미세 차이는 드러나나, 출처 관행을 넘는 정밀도로 오해 유발 |
| 카드는 2자리, 지도는 1자리 | 같은 지표가 화면마다 달라져 혼란 |
| **소수 1자리 통일 + 원자료 4자리 제공** | 채택 |

**새로운 결정**
UI 표시는 **소수 1자리**로 통일한다. 전체 정밀도(4자리)는 CSV·JSON 다운로드와 데이터 사전에서 제공하고, 출처 패널에 계산식을 명시한다. `product-requirements.md` §4.1의 예시를 `4.0%`로 정정했다.

**영향**
- 데이터: 없음 (저장은 그대로 4자리)
- 보안: 없음
- 사용자 경험: 화면 전체가 일관된 정밀도. 연구용 정밀값은 다운로드로 접근

## DL-006. mock 데이터 미사용

**기존 결정**
구현 지시서 §2 Phase 2는 mock 데이터 사용 시 조건(`mock` 디렉터리, "예시 데이터" 표시, 프로덕션 제외 등)을 규정한다.

**변경 이유**
기획 단계에서 **실제 공식 데이터 스냅숏(540 레코드)을 이미 확보**했다 (`data/snapshots/multicultural-students.v1.json`). UI 개발에 mock이 필요하지 않다.

**새로운 결정**
mock 데이터를 **생성하지 않는다.** 개발·테스트 전부 실제 스냅숏을 사용한다. 지시서 §10-19("mock 데이터가 프로덕션에 포함되지 않는다")는 mock이 존재하지 않음으로 충족한다.

**영향**
- 데이터: 개발 중에도 실제 값을 보므로 이상값을 조기에 발견
- 사용자 경험: "예시 데이터" 배지가 실수로 남을 위험 자체가 없음
